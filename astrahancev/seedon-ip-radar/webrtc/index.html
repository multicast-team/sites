📖 Полезные материалы

Как возникает утечка WebRTC?

WebRTC (Web Real-Time Communication) — технология, встроенная в браузер для голосовых и видеозвонков без плагинов.

При установке прямого P2P-соединения браузер отправляет UDP-запрос к STUN-серверу, чтобы узнать ваш внешний IP-адрес. Поскольку обычные HTTP-прокси пропускают только TCP-трафик, UDP-запрос может уйти напрямую через провайдера и раскрыть ваш реальный IP.

Что проверяет этот инструмент?

Страница отправляет запросы к нескольким STUN-серверам (Google, Cloudflare) и сверяет полученные кандидаты с вашим основным выходным IP:

  • Проксирование UDP — если STUN возвращает адрес вашего прокси, значит UDP идёт через туннель.
  • Утечка реального IP — если STUN возвращает IP домашнего провайдера при включённом прокси, значит UDP обходит туннель.
  • Блокировка не проксируемого UDP — если список кандидатов пуст, значит браузер или файрвол надёжно блокирует прямые UDP-пакеты.
Что такое STUN и UDP?

UDP (User Datagram Protocol) — быстрый транспортный протокол без предварительного рукопожатия, используемый в звонках, стриминге и онлайн-играх.

STUN (Session Traversal Utilities for NAT) — служебный протокол, позволяющий устройству за роутером (NAT) узнать свой публичный IP-адрес и порт.

Как интерпретировать результат?
  • Безопасно (утечек нет): адрес WebRTC совпадает с выходным IP прокси, либо WebRTC отключён / не возвращает публичных кандидатов.
  • Обнаружена утечка: WebRTC возвращает дополнительный публичный IP вашего локального интернет-провайдера.
Как защититься от утечки WebRTC?

Opera / Chrome / Brave: установите политику WebRTC в режим disable_non_proxied_udp («Отключить не проксируемый UDP») или включите защиту WebRTC в uBlock Origin.

Firefox: в about:config установите media.peerconnection.ice.proxy_only_if_behind_proxy = true и media.peerconnection.ice.default_address_only = true (или media.peerconnection.enabled = false).

Клиент прокси (Clash / Mihomo / Sing-box): добавьте правило блокировки прямого UDP или направьте STUN через прокси/TUN.

Почему режим системного прокси и TUN дают разный результат?

Системный прокси (HTTP/SOCKS5): браузер видит активный прокси и при политике disable_non_proxied_udp не отправляет прямые UDP-пакеты к STUN-серверам — поэтому статус отображается как «Отключено / Утечек не обнаружено».

Режим TUN (виртуальный сетевой адаптер): перехватывает весь трафик системы на сетевом уровне (и TCP, и UDP), поэтому STUN-запрос проходит через VPN-туннель и возвращает выходной IP вашего VPN-сервера.
