DNS Что такое утечка?Почему это важно?

Простыми словами, При каждом обращении к сайту, браузер обращается к DNS серверу: "чтобы определить адрес домена IP какой адрес используется?"Это похоже на поиск в телефонной книге — вы вводите имя, и получаете номер.

В чём проблема: ваш DNS История запросов, может раскрывать посещаемые домены.

Обычно, при использовании прокси, трафик идёт через зашифрованный канал. Однако важно проверить, DNS запросы могут обходить прокси, и отправляться непосредственно локальному оператору DNS Сервер.

Что это означает?Пользователь рассчитывает на"Конфиденциальность" , но оператор может видеть домены, запрошенные через его DNS. Это и есть Утечки DNS.

Кроме того, некоторые операторы используют"Прозрачный DNS Прокси" — Даже после ручного изменения DNS Настройки (например на 8.8.8.8), ваш DNS запросы могут перехватываться и перенаправляться оператором. Это не всегда заметно, Запросы при этом доступны резолверу.

поэтому, Одного включения прокси может быть недостаточно. Проверьте DNS что запросы идут через ожидаемый канал, иначе часть сетевой активности остаётся видимой.

Обнаружено DNS обнаружена утечка, Как исправить?

Основной принцип: После подключения прокси, используйте выбранный вами DNS Сервер, вместо DNS локального оператора.

🌐 Настройки браузера

Chrome, Edge, Firefox и другие современные браузеры поддерживают"Безопасность DNS"или"DNS over HTTPS"соответствующую функцию. Она повышает конфиденциальность (Шифрование DNS), но может использовать маршрут, отличный от настроек прокси, приводит к DNS Браузер может выбрать собственный DNS сервер вместо резолвера прокси.

при использовании прокси, Проверьте настройку браузера"Использовать защищённый DNS", Чтобы DNS и маршрут DNS через прокси.

💻 Настройки системы

Windows Пользователь: Откройте командную строку, Выполните ipconfig /flushdns Сбросить DNS Разрешение имён. Затем в настройках сетевого адаптера, Направьте DNS укажите адрес выбранного DNS-сервера.

Mac Пользователь: в"Системные настройки → Сеть"удалите ненужные ручные записи DNS, и проверьте автоматическую настройку клиента. Выполните в терминале sudo dscacheutil -flushcache Сбросить DNS Разрешение имён.

🔧 Настройка клиента прокси

Если используете клиент прокси, Убедитесь DNS проверьте, включены ли"DNS Перехват"или"fake-ip"Режим. Тогда все DNS запросы будут обрабатываться клиентом, без прямого обращения к локальному резолверу.

После изменения, повторите тест на этой странице, и проверьте результат.

Почему при включённом прокси, DNS возможна утечка?

Включение прокси не гарантирует маршрутизацию всех протоколов, DNS Проверьте, идут ли запросы через него. На практике: в некоторых конфигурациях прокси, DNS используется локальная сеть. Это DNS Частые причины утечек.

Причина 1: Клиент не перехватывает DNS

HTTP/SOCKS5 Прокси перенаправляет только TCP Соединение. Перед отправкой TCP соединения, браузер выполняет DNS разрешение имени для получения целевого IP. Если клиент не настроен на"Удалённый DNS Разрешение имён" (Remote DNS), Текущий DNS запросы могут уйти DNS-серверу оператора DNS Сервер — и раскрыть запрашиваемые домены.

Причина 2: Система DNS и прокси DNS Не совпадает

Даже если в клиенте настроен DNS, системный DNS может использовать другие настройки. Некоторые приложения (особенно работающие вне браузера)не используют DNS прокси DNS, а обращаются к системному DNS, Часть трафика идёт через прокси DNS, а часть — напрямую DNS, Выходной IP обнаружено"Разделение".

Причина 3: IPv6 DNS Обход прокси

Распространённый источник расхождений: Некоторые правила охватывают только IPv4 для DNS Запрос. Если в системе включён IPv6, AAAA Записи типа DNS запрос может уйти напрямую через оператора. Поэтому в прокси-конфигурации стоит проверить Отключить IPv6 соответствующие настройки.

Как проверить конфигурацию?

  • TUN Режим: Используйте TUN/режим виртуального адаптера вместо системного прокси, если это необходимо, чтобы нужный трафик (Включая DNS для UDP Запрос)проходил через прокси
  • Встроенный в прокси DNS: Включите в клиенте DNS Перехват или fake-ip Режим, Проверьте все DNS обработку запросов клиентом
  • DoH/DoT: Настройте в системе или браузере DNS зашифрованный DNS DNS (DoH), Даже при прямом маршруте, содержимое DNS-запроса будет зашифровано
  • Отключить IPv6: Избегайте IPv6 DNS запросы не должны обходить нужные правила

После изменения конфигурации, повторите проверку. Если показаны только ожидаемые резолверы DNS Выходной IP, маршрут соответствует настройке.

DoH, DoT, Обычный DNS В чём разница?Что выбрать?

При открытии сайта, браузер выполняет DNS Проверка, преобразование домена в IP Адрес. Есть три распространённых способа DNS-запроса:

Обычный DNS (Порты 53): Традиционный способ, Запрос передаётся без шифрования. Оператор, Маршрутизатор, Общедоступный WiFi или оператор сети может видеть запрошенный домен. Помимо риска для конфиденциальности, возможна подмена ответа — Ответ может быть заменён рекламной страницей или неверным IP.

DoT (DNS over TLS, Порты 853): Направьте DNS Запрос передаётся в TLS зашифрованном туннеле. Посредник не видит содержимое запроса, но видит соединение с DNS DNS-сервером (Поскольку 853 Порт легко распознаётся). Некоторые сети могут его блокировать 853 Порты.

DoH (DNS over HTTPS, Порты 443): Направьте DNS Запрос передаётся как обычный HTTPS Трафик. Посредник не видит содержимое, и ему сложнее отличить DNS DNS-запрос от обычного веб-трафика. Это один из вариантов защиты DNS-запросов.

WebRTC Что такое утечка?

WebRTC Встроенная в браузер технология, используется для видеосвязи, голосовых звонков и общения в реальном времени. Сама технология полезна, Однако возможен побочный эффект: Соединение может обойти прокси, и раскрыть фактический IP.

Как это работает: WebRTC Для прямого соединения устройств, использует STUN сервер определяет внешний адрес IP. При этом используется UDP Протокол, а многие прокси поддерживают только TCP Трафик. Поэтому даже с включённым прокси, WebRTC может быть раскрыт ваш фактический IP адрес.

На веб-странице JavaScript код может вызвать проверку без отдельного уведомления WebRTC, и получить ваш IP Адрес. отдельный запрос разрешения может не появиться.

Как настроить защиту?

  • Firefox: Введите в адресной строке about:config, Найдите media.peerconnection.enabled, Установить false
  • Chrome / Edge: Установите uBlock Origin Расширение, Доступна настройка"Блокировать WebRTC Раскрытие локального IP"соответствующая настройка
  • Brave: Настройки → Конфиденциальность → WebRTC IP Политика обработки, Выберите"Отключить вне прокси UDP"
